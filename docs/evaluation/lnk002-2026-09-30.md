# LNK002 fresh holdout

Recorded on 2026-09-30 for [issue 11](https://github.com/scarletkc/seiso/issues/11).
LNK002 stays in preview. On ten repositories it had not seen before, 96 of its
451 diagnoses were broken links. Its conservative precision, which counts the
49 uncertain results against the rule, is 21.3%, against the 95% that
[promotion](policy.md#stable-promotion) requires. Without the uncertain
results, precision is 23.9%.

## Method

The rule was frozen before the repositories were pinned. The
[selection](../../corpus/results/lnk002/fresh-v1/sources.json) lists 25
documentation-heavy repositories in four batches, and the first batch already
reached 100 diagnoses. Each diagnosis was judged on the page its readers see:
the documentation site when the repository publishes one, and GitHub otherwise.
Two agents labeled every diagnosis independently and agreed on 443 of 451.
Checking the renderer settled the rest.

## Causes

- **Site generators make anchors differently from GitHub (229 FP).** VitePress
  turns the heading `vi.fn` into `vi-fn` where GitHub produces `vifn`; Vitest
  alone has 206 of these. MkDocs differs in similar ways.
- **Anchor syntax LNK002 does not read (8 FP),** such as `{ id="9.7.0" }` and
  raw HTML headings.
- **Anchors created during the build (69 FP, 49 uncertain),** such as ids from
  mkdocs-material's build hooks and Liquid variables in vscode-docs headings.

The [labels](../../corpus/results/lnk002/fresh-v1/batch-1/annotations/labels-links.json)
give the cause of each diagnosis. [Issue 57](https://github.com/scarletkc/seiso/issues/57)
fixes these causes with this batch as tuning data, and
[issue 58](https://github.com/scarletkc/seiso/issues/58) plans the next
holdout. Vitest supplied 59% of the diagnoses; that was not assessed because
precision already failed, and issue 58 caps each source instead.
