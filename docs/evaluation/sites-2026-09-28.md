# Documentation site routes

Recorded on 2026-09-28. `[[sites]]` entries let LNK001 and LNK002 resolve
links as routes of a documentation site, as [LNK001](../rules/LNK001.md#inputs)
describes. This record measures that resolution on the pinned corpus. It does
not promote LNK002.

## Inputs

Both runs check the same 1,953 documents and pinned Git trees with the
evaluator used for M3. The
[site profile](../../corpus/evaluation/sites.json) gives 13 sources one entry
each. Every entry cites a VitePress, Docusaurus, mdBook, MkDocs, or Jekyll
configuration, or a site navigation file, read at the source's pinned commit.
Sources without one, or whose corpus documents lie outside the site, have no
entry. The entries are agent-reviewed evaluation assumptions, not upstream
declarations.

## Without site entries

The [run without the profile](../../corpus/results/sites-v1/plain/run.json)
produces the same raw result, byte for byte, as the same evaluator on the
preceding `main` revision: 4,072 diagnoses, 2,162 of them LNK001.

## With site entries

The [run with the profile](../../corpus/results/sites-v1/sites/run.json)
reports 176 LNK001 diagnoses. The [review](../../corpus/results/sites-v1/review.json)
re-resolves each of the 1,986 removed diagnoses against the pinned tree; the
reproduction matches the removed set exactly. Each link now reaches a page
source or file at its route:

| Resolution | Diagnoses |
| --- | ---: |
| `.md` added to the route | 1,458 |
| `.html` route to its `.md` source | 424 |
| `index` page in the route's directory | 46 |
| File at the route path | 27 |
| File in the site's `public` directory | 21 |
| `.mdx` added to the route | 7 |
| mdBook `index.html` to `README.md` | 3 |

No removal rests on a route directory without a page. The 14 LNK001 diagnoses
in documents outside any site are unchanged. The 162 that remain in site
documents change only their suggestion, which now names the site root. The
review labels whether each link is broken for readers of the published site:

| Cause | Diagnoses | Broken on the site |
| --- | ---: | --- |
| Page generated at build time (ruff, uv, goose) | 150 | No |
| Date permalink of a blog post (aider, goose) | 4 | No |
| Page rendered by a React component (goose) | 4 | No |
| Generated category index (goose) | 1 | No |
| Lowercase route to `docs/CONTRIBUTING.md` (gemini-cli) | 1 | No |
| Route with no page (rust-examples-ja) | 1 | Yes |
| Route to another publication on the host (rust-examples-ja) | 1 | Undetermined |

LNK001 documents suppression, with a reason naming the build step, for pages a
build generates. Permalinks, component pages, generated indexes, and case
folding depend on generator behavior that the route candidates do not model.

## LNK002 on route targets

Anchors on route targets become checkable, adding 51 LNK002 diagnoses. 43 are
broken on the site. In 38, rust-book-zh keeps the original book's English
fragments while the target headings are translated and declare no id, so
mdBook generates different anchors. The other 5 name ids that the target no
longer declares (vue-zh 4, goose 1). The remaining 8, in vue-ja and vue-zh,
link into pages that a Vue component renders at runtime, so their anchors
have no Markdown source. PTR002 and the other cross-file rules report no
change.

## Limits

Labels are agent reviews of the original sources, pinned trees, and generator
configuration; no human labeling is claimed. The corpus was selected before
this change and is not a fresh holdout for LNK002. Reproduce the runs and
their comparison with the
[evaluation procedure](../../corpus/docs/evaluation.md#documentation-site-routes).
