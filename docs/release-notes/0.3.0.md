## Documentation-site links, additive inheritance, and more platforms

seiso 0.3.0 resolves links written as documentation-site routes, lets child
configurations add to inherited lists, links each diagnostic to its rule page,
and adds prebuilt binaries for musl-based Linux and Windows on arm64. The
default rule set is unchanged: KND001, KND002, LNK001, SUP001, and SUP002.

### New

- **Documentation sites**: a `[[sites]]` entry marks the documents that a site
  generator such as VitePress, Docusaurus, mdBook, or MkDocs renders. LNK001
  and LNK002 then resolve links such as `/guide/setup` or `setup.html` as
  routes of that site and check anchors in the routed page. `seiso init`
  suggests an entry for each site project it finds; the
  [configuration reference](https://github.com/scarletkc/seiso/blob/v0.3.0/docs/reference/configuration.md#documentation-sites)
  describes the fields.
- **Additive inherited lists**: `extend-exclude`, `lint.extend-select`, and
  `lint.extend-ignore` append to the effective `exclude`, `lint.select`, and
  `lint.ignore` lists across the `extend` chain, so a child configuration no
  longer copies its parent's list to add one entry.
- **Rule links**: each JSON diagnostic from a registered rule has a `url` to
  the rule's page at the release tag matching the binary, and SARIF gives each
  rule the same link as `helpUri`. `seiso rule` points the relative links in
  rule pages at that tag, so they open outside a seiso checkout.
- **Platforms**: the PyPI and npm packages include prebuilt binaries for Linux
  x64 and arm64 with musl, such as Alpine, and for Windows on arm64.

### Improved

- When a link's letter case differs from its target's name, LNK001 names the
  file as spelled on disk instead of reporting a missing target. In a
  documentation site, a route written in lowercase still reaches a page
  source whose name has capitals.
- Checks extract heading and HTML anchors only for documents whose anchors a
  link or `seiso index --dump` reads.

### Upgrade notes

- JSON diagnostics from registered rules have a string `url` instead of
  `null`, and SARIF rule descriptors include `helpUri`.
- On Windows and macOS, LNK001 now reports links whose letter case differs
  from the file, as it already did on Linux. LNK002 and the other rules that
  look up linked documents treat such a target as missing.
- `@scarletkc/seiso` on npm now installs its binary from one
  `@scarletkc/seiso-PLATFORM` package, declared as an optional dependency.
  Installing with `--omit=optional` or `--no-optional` leaves `seiso` without
  a binary.

### Known limitations

- Glob patterns that a child inherits through `extend`, including
  `extend-exclude`, resolve from the child's directory rather than the
  parent's ([#40](https://github.com/scarletkc/seiso/issues/40)). Fixing this
  will change which files those patterns match.
- Platforms other than those listed in the
  [README](https://github.com/scarletkc/seiso/blob/v0.3.0/README.md#install)
  have no prebuilt binary; install with `cargo install seiso`.
- Preview rules can change before promotion. Each rule becomes stable only
  after meeting the
  [evaluation policy](https://github.com/scarletkc/seiso/blob/v0.3.0/docs/evaluation/policy.md).
