## Heuristic rules, clearer checks, and more platforms

seiso 0.2.0 adds nine heuristic preview rules, prebuilt binaries for macOS and
Linux arm64, and fixes for problems found while using seiso on real projects.
The default rule set is unchanged: KND001, KND002, LNK001, SUP001, and SUP002
run by default, and the new rules run only with `--preview`.

### New

- **Heuristic preview rules**: deployment-state assertions (STL002),
  unconstrained versions (STL004), rationale before a procedure (RAT001), long
  preambles (ORD001), exceptions before the main flow (ORD002), conflicting
  section responsibilities (MIX001), excluded-scope headings (VOX002),
  production narration (VOX003), and evaluative claims without evidence
  (EVD001). `seiso rule <CODE>` explains each one with examples.
- **Section classification**: `seiso parse` reports each section's heuristic
  role with its source evidence, as described in the
  [section reference](https://github.com/scarletkc/seiso/blob/v0.2.0/docs/reference/sections.md).
- **Platforms**: the PyPI and npm packages include prebuilt binaries for macOS
  on Apple silicon and Intel and for Linux arm64, in addition to Linux x64 and
  Windows x64.

### Improved

- `seiso check` explains a named path or a workspace that selects no document:
  it is not Markdown, `.gitignore` ignores it, the configuration excludes it or
  does not include it, or it contains no Markdown files. A command-line rule
  selector that names only preview rules warns when preview is off.
- `seiso init` writes at the repository root, excludes existing issue and pull
  request templates, dependency directories, and adopted texts such as a code
  of conduct, and maps contributing, security, and support guides to `howto`.
- Chinese and Japanese prose that names English identifiers keeps its
  language: detection ignores inline code and link destinations and counts
  Latin words instead of letters.
- LNK002 reads heading attribute lists such as `{#install}` as anchors.
- STL001 no longer repeats a value that STL003 or STL004 reports, and VOX003 no
  longer reports a notice that a page is generated or maintained by someone.
  VOX001 also reports phrases that relay what the requester confirmed or
  authorized, such as `the user confirmed` and `经用户确认`.
- The parse cache adds its own `.gitignore` and `CACHEDIR.TAG` and removes
  entries older than a week.
- `seiso rule` accepts lowercase codes, and an unknown rule or selector names
  the installed version.
- Frontmatter errors report file line numbers, and text output ends with the
  number of diagnostics.

### Upgrade notes

- With `--config PATH`, the workspace is the repository around the calling
  directory, and the configuration's patterns apply from that root. A
  configuration stored in a subdirectory could previously check nothing.
- The default `include` also matches `.markdown` files. Add them to `exclude`
  to keep them unchecked.
- A suppression that named STL001 for a version or commit value now needs
  STL004 or STL003, and SUP002 reports the unused STL001 code. All three
  STL rules are in preview.
- Diagnostic messages changed for several rules and now end with periods.
  Scripts should match the `code` field rather than message text.
- Existing parse cache entries are rebuilt once.

### Known limitations

- Alpine and other musl-based Linux, and Windows on arm64, have no prebuilt
  binary; install with `cargo install seiso`.
- Preview rules can change before promotion. Each rule becomes stable only
  after meeting the
  [evaluation policy](https://github.com/scarletkc/seiso/blob/v0.2.0/docs/evaluation/policy.md).
