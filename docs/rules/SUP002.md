# SUP002: Unused suppression

## What it checks

Reports a rule code in a valid suppression when that rule completed for the file
and the declaration suppressed no diagnostic for that code.

## Basis

Consistency. An exemption is needed only while it covers a diagnostic from an
enabled, completed check.

## Why it matters

An obsolete exemption can hide a later mistake. A guide that once linked to a
generated page may retain its link exemption after that link is removed, hiding
a new broken link added to the same paragraph.

## Example

With `LNK001` and `SUP002` enabled:

```markdown
<!-- seiso: allow LNK001 -- The linked guide is generated at release time. -->

The command prints its version.
```

## Instead

```markdown
The command prints its version.
```

## Exceptions

Codes excluded by selectors, preview status, per-file ignores, or document kind
have the `rule_disabled` state. Checks with incomplete inputs have the
`incomplete` state, even if an exemption suppressed some known diagnostics.
Neither case is reported as unused. Each code in a declaration has its own state.

A valid exemption for `SUP002` can suppress another declaration's unused-code
diagnostic. A declaration cannot suppress its own unused-code diagnostics.
Unused `SUP002` exemptions are reported after that matching step and cannot
suppress one another; exemption evaluation does not recurse.

## Inputs

Reads valid declarations, their scopes, per-rule completion, and suppression hit
counts. Only the winning exemption receives a hit when scopes overlap. No
filesystem or workspace index is read directly; the checked rule supplies its
completion state.

## Configuration

Select or ignore `SUP002` through the rule selectors. There are no thresholds or
word lists.

`seiso policy` inspects declarations without running rules. Enabled codes have
the `not_evaluated` state. Use `seiso policy --evaluate` to check whether each
exemption is active, stale, or incomplete.

## Fix

`seiso check --fix` removes the reported unused codes. Other codes and the reason
remain in a mixed declaration. When no codes remain, the comment is removed;
its line is removed only when that line contains no other content and removing
it does not join neighboring content lines. Inline comments leave surrounding
text and whitespace intact.

Disabled, incomplete, invalid, active, and suppressed unused-code diagnostics
never authorize removal. A file must still match the checked source before its
edits are written.
