# RAT001: Rationale before a procedure

## What it checks

At least two decision-argument paragraphs totaling at least 160 visible characters before the first actionable instruction, command, or ordered procedure in a how-to or reference.

## Basis

How-to and reference readers need the procedure or contract before an extended argument for the implementation choice.

## Example

```markdown
---
kind: howto
---
We chose this database because our team needed to compare several persistence models and their operational costs.

The alternative required a different deployment design, and our decision followed a long discussion about the maintenance trade-offs.

1. Run `db start`.
```

## Instead

```markdown
---
kind: howto
---
1. Run `db start`.

Read the decision record for the database selection rationale.
```

## Exceptions

A page without a detected main flow is undetermined, emits no diagnosis, and preserves its suppressions. Ordinary prerequisites and short explanations are not extended decision arguments. Quoted phrases do not supply decision evidence. Examples inside troubleshooting or quotations do not establish the main flow. Opaque containers or unclassified code examples before it leave ordering undetermined and preserve suppressions.

## Inputs

Visible paragraph prose and document structure are read. The diagnostic links to the first detected main-flow block.
