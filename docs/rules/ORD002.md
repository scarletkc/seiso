# ORD002: Exceptions before the main flow

## What it checks

A troubleshooting, FAQ, known-issues, or exceptions heading before the main flow in a how-to or runbook.

## Basis

Heuristic. Troubleshooting, FAQ, known-issues, or exceptions headings before the main flow suggest recovery paths placed ahead of the procedure.

## Why it matters

Readers follow the common procedure before consulting recovery paths and exceptions.

## Example

```markdown
---
kind: howto
---
## Troubleshooting

Restart the server if connection fails.

## Connect

1. Run `app connect`.
```

## Instead

```markdown
---
kind: howto
---
## Connect

1. Run `app connect`.

## Troubleshooting

Restart the server if connection fails.
```

## Exceptions

Pages with no detected main flow, including standalone recovery pages, emit no diagnosis and preserve incomplete suppression states. Nested recovery headings produce one diagnosis at their outermost section. Warnings and prerequisites do not count as recovery headings.

## Inputs

Section annotations and block order are read. Commands inside recovery sections or sample output do not become the main flow. Opaque containers or unclassified code examples before the flow leave ordering incomplete.
