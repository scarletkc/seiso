# KND001: Missing document kind

## What it checks

Reports a file whose kind cannot be resolved because its frontmatter is
invalid, or neither frontmatter nor a matching configuration entry assigns a kind.

A leading `---` and prose labels such as `Note:` alone do not establish
frontmatter. Without a closing YAML fence, Seiso infers unclosed frontmatter
only from a top-level `kind`, `lang`, or `canonical` field in the initial
mapping. Nested fields, code examples, HTML blocks, and blockquotes do not
establish a declaration, so ordinary thematic-break documents can use a
configured kind.

## Basis

Consistency. A document needs a declared responsibility before kind-specific
rules can run. Invalid frontmatter prevents a configured kind from taking effect.

## Why it matters

A deployment guide with no kind cannot be checked against the runbook or
howto contract. Only KND, LNK, and SUP rules apply until its kind is resolved.

## Example

```markdown
---
kind: [howto
---

# Install

Run the installer.
```

## Instead

```markdown
---
kind: howto
---

# Install

Run the installer.
```

## Exceptions

Use a path mapping for documents that cannot carry frontmatter. A temporary
`allow-file KND001` suppression needs a reason and leaves kind-specific rules disabled.

## Inputs

YAML frontmatter and the effective kind mapping. No filesystem lookup or
repository index is required.

## Configuration

Use `[[kinds]]` to assign kinds by path. Frontmatter takes precedence.
