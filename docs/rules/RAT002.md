# RAT002: Design-choice headings

## What it checks

A how-to or reference heading starts with a phrase explaining a design choice.

## Basis

This normative rule enforces the `howto` and `reference` kind contracts: procedures and contracts have different responsibilities from decision records.

## Why it matters

A connection guide that opens with a database-selection argument delays the connection steps and keeps that argument alive after the database changes.

## Example

```markdown
---
kind: howto
---
## Why we chose Redis
```

## Instead

```markdown
---
kind: howto
---
## Connect to Redis
```

## Exceptions

Troubleshooting questions such as “Why does the connection fail?” are outside this rule. Put the design decision in an ADR and link to it. Suppress a heading only when the rationale must be part of that procedure or contract, with a reason explaining that dependency.

## Inputs

Only heading text and heading link labels are read. Inline code, URLs, body paragraphs, and code blocks cannot trigger the rule. Japanese headings also match `なぜ…を選んだ` and related explicit choice phrases. No filesystem or workspace index is required.

## Configuration

Use `lint.lexicon.<language>.extend-rationale-headings` to add literal heading prefixes. English prefixes ignore ASCII case and respect word boundaries. Chinese and Japanese prefixes use character matching. `lint.languages` selects the sentence languages to check.
