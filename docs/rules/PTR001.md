# PTR001: Repository-root pointers

## What it checks

A sentence directs the reader to a link whose target is a repository root.

## Basis

This normative rule applies to every kind except `changelog`; generated files follow the configured generated-file policy. A pointer should locate the fact it promises.

## Why it matters

An API reference that sends readers to a repository homepage makes each reader search again for the definition.

## Example

```markdown
---
kind: reference
---
See the [configuration source](/).
```

## Instead

```markdown
---
kind: reference
---
See [`Config::load`](../src/config.rs).
```

## Exceptions

A project directory may intentionally link to project homepages. Suppress those pointers with a reason describing the directory's purpose.

## Inputs

Pointer phrases read ordinary text and link labels. Links include inline and reference links, excluding images. Relative paths resolve from the document; leading `/` resolves from the workspace root. The rule also recognizes two-component repository paths on GitHub, GitLab, Codeberg, and Bitbucket. Links with a query or fragment are outside this check. It uses path context, without accessing the filesystem or workspace index.

## Configuration

Use `lint.lexicon.<language>.extend-pointer-markers` to add phrases. Built-in phrases include `see`, `defined in`, `见`, `定义在`, and `参照`. `lint.languages` selects the sentence languages to check.
