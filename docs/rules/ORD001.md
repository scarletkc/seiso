# ORD001: Long preambles

## What it checks

More than 30 occupied prose/table lines, or a table longer than 10 lines, before a detected main flow in a how-to or runbook.

## Basis

Heuristic. The amount of prose and table content before the detected main flow suggests that background delays the procedure.

## Why it matters

A usable entry point precedes extended background and reference tables in a page that teaches an operation.

## Example

```markdown
---
kind: howto
---
| Setting | Value |
| --- | --- |
| setting_0 | value |
| setting_1 | value |
| setting_2 | value |
| setting_3 | value |
| setting_4 | value |
| setting_5 | value |
| setting_6 | value |
| setting_7 | value |
| setting_8 | value |
| setting_9 | value |

1. Run `app start`.
```

## Instead

```markdown
---
kind: howto
---
1. Run `app start`.

| Setting | Value |
| --- | --- |
| port | 8080 |
```

## Exceptions

YAML, headings, blank lines, comments, quotations, and code fences do not count toward the preamble. Actionable prose, ordered procedures, shell commands, and configuration examples introduced by an instruction establish the main flow. Console output and sample conversations do not. Reference pages may lead with catalogs and are outside this rule. Opaque HTML, component containers, or unclassified code examples before the flow leave the rule incomplete, preserving its suppressions. Pages with no detected flow also remain incomplete and emit no diagnosis.

## Inputs

Block structure and occupied source lines are read. The related location identifies the delayed main flow.
