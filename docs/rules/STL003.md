# STL003: Embedded commit identifiers

## What it checks

A commit, SHA, or build context is immediately followed by a hexadecimal identifier of 7 to 40 characters.

## Basis

This normative rule applies to [long-lived documents](../../spec/convention.md#document-kinds), which point to the authority for a moving identifier.

## Why it matters

A runbook with a manually copied deployed commit can send an operator to the wrong source after the next deployment.

## Example

```markdown
---
kind: runbook
---
The deployed commit is listed as build `a1b2c3d`.
```

## Instead

```markdown
---
kind: runbook
---
Read the deployed commit from the deployment record.
```

## Exceptions

A reproducibility procedure may require an immutable commit. Suppress the sentence with a reason identifying that requirement. Put dated deployment results in a changelog.

## Inputs

Ordinary text, link labels, and inline code are checked. Code blocks, URLs, and link destinations are excluded. Whitespace, `:`, `=`, and `#` may separate a context from its identifier. Other words between them prevent a match. No filesystem or workspace index is required.

## Configuration

Use `lint.lexicon.<language>.extend-commit-contexts` for additional contexts. The built-in contexts include English `commit`, `sha`, and `build`; Chinese `提交` and `构建`; and Japanese `コミット` and `ビルド`. `lint.languages` selects the sentence languages to check.
