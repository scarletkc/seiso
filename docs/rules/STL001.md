# STL001: Current-state values

## What it checks

A sentence contains a current-state marker and a version, hash, image tag, or count, without a requirement or range marker.

## Basis

This normative rule applies to [long-lived documents](../../spec/convention.md#document-kinds). These documents describe lasting behavior and procedures.

## Why it matters

A setup guide that snapshots a deployed version needs a manual edit after every release. Readers can mistake that snapshot for a supported-version requirement.

## Example

```markdown
---
kind: howto
---
The service currently uses `v1.2.3`.
```

## Instead

```markdown
---
kind: howto
---
The service requires version `1.2.3` or later.
```

## Exceptions

A compatibility example may need a frozen value. Suppress that sentence with a reason naming the tested scenario. A dated release snapshot belongs in a changelog.

When `STL003` or `STL004` reports the same value, this rule leaves it to that more specific diagnosis.

## Inputs

Markers read ordinary text and link labels. Values and constraints also read inline code. URLs, link destinations, and code blocks are excluded. A value and marker must occur in the same sentence. This rule does not read the filesystem or a workspace index.

## Configuration

Use `lint.lexicon.<language>.extend-stale-markers` and `extend-constraint-markers` to add phrases for `en`, `zh`, or `ja`. English phrases use word boundaries and ignore ASCII case. Chinese and Japanese phrases use character matching. `lint.languages` selects the sentence languages to check. Numeric range signs and a version followed by `+` also exempt a sentence. A marker inside inline code does not trigger the rule.
