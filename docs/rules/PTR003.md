# PTR003: Unlocated source pointers

## What it checks

A sentence says to `see the source` without naming a recognizable source file or symbol.

## Basis

This normative rule applies to every checked kind. A source pointer should give the reader a place to start.

## Why it matters

A guide that says `see the source` leaves a new contributor to search the entire codebase before continuing.

## Example

```markdown
---
kind: howto
---
For configuration loading, see the source.
```

## Instead

```markdown
---
kind: howto
---
For configuration loading, see the source in `src/config.rs`, at `Config::load`.
```

## Exceptions

A source-browsing exercise may intentionally omit the answer. Suppress it with a reason describing the exercise. A repository homepage alone does not identify a file or symbol.

## Inputs

Pointer phrases read ordinary text and link labels. The same sentence is searched for paths and symbols in ordinary text, link labels, inline code, and link destinations. Recognized targets include common source/configuration/document extensions, `Dockerfile`, `Makefile`, link fragments, qualified symbols, snake case, camel case, constants, and identifiers in inline code. URLs in prose and code blocks are excluded. This check does not establish whether the named target exists and does not read the filesystem or index.

## Configuration

Use `lint.lexicon.<language>.extend-source-pointers` to add phrases. Built-in phrases include `see the source`, `见源码`, and `ソースを参照`. `lint.languages` selects the sentence languages to check.
