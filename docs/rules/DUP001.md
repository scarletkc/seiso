# DUP001: Repeated identifier definitions

## What it checks

Compares definition lists and tables across files in the same language and
configured domain. A qualifying pair shares at least five distinct inline-code
identifiers and has identifier-set Jaccard similarity of at least 0.8.

## Basis

Heuristic. Matching identifier sets suggest that two blocks maintain the same facts.

## Why it matters

Duplicated configuration descriptions can diverge when one document is updated.

## Example

In `guide.md`, when `reference.md` defines these same five settings:

```markdown
---
kind: howto
---

- `host`: Server address.
- `port`: Listening port.
- `user`: Account name.
- `token`: Access token.
- `timeout`: Request timeout.
```

## Instead

```markdown
---
kind: howto
---

See [the settings reference](reference.md#settings).
```

## Exceptions

Bare lists of identifiers and prose mentions are not definitions. A definition
list item starts with an inline-code key and includes a description. A table
defines inline-code keys in its first column and describes them in other columns.
Code blocks are excluded. Translations and different configured domains are
compared separately.

## Inputs

All inline-code identifiers within qualifying definition blocks are compared.
Each pair is ranked by the
[ownership precedence](../reference/convention.md#facts-and-pointers).
Reports appear on the lower-ranked side with every directly matching
higher-ranked source in `related`. A highest-rank tie uses `OWN002`.

## Configuration

Enable preview and select `DUP001`. `[lint.dup] min-identifiers` and
`min-jaccard` control the thresholds. Use `[[domains]]` to separate unrelated
vocabularies and `canonical: true` to declare an authoritative document.
