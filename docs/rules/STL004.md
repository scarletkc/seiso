# STL004: Unconstrained versions

## What it checks

A standalone version label or explicit version-state assertion in a long-lived page, without a requirement or historical context.

## Basis

A maintained page can state a compatibility requirement. The manifest or release record owns a package version observed at one point in time.

## Example

```markdown
---
kind: howto
---
The package version is `2.4.1`.
```

## Instead

```markdown
---
kind: howto
---
The package requires version `2.4.1` or later.
```

## Exceptions

Requirements, comparison operators, bounds such as “prior to” and “or higher”, compatibility statements, historical introductions, license names, and examples introduced by “such as” or quoted as prose are excluded. Detection requires a standalone version/release label or a state relation such as “version is” or “runs version”. A version mention by itself is insufficient. Unlabeled decimals, paths, model names, and code blocks are not version evidence.

## Inputs

Visible prose, link labels, and inline code are read; URLs are masked. The existing constraint-marker lexicon also applies.

[Rule and language selection](../reference/configuration.md#rule-selection).
